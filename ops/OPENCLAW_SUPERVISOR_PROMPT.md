# Property Rental deterministic supervisor contract

This document is an operator-readable contract. The dispatcher must never inject it into an implementation or review session.

The OpenClaw schedule runs `scripts/openclaw-supervisor-dispatch.sh`. That entry point performs only compact-state reconciliation, deterministic roadmap selection, stage routing, lock and process monitoring, failure classification, durable evidence management, publication-state reconciliation, and health/progress signaling. It must not perform model-heavy product work.

Every candidate has these separately persisted stages: reconciliation and dispatch, implementation, deterministic verification, independent review, publication, post-publication reconciliation, and next-candidate activation. Each model stage is a unique fresh one-shot session receiving only the deterministic compact packet built from current state, exact fingerprints, the roadmap item, its routed authorities, its include/exclude boundaries, acceptance criteria, durable evidence paths, authorization boundaries, and output contract. Full supervisor prompts, prior transcripts or reasoning, unrelated diffs or canonical documents, raw logs, and stale errors are forbidden inputs.

Implementation uses the repository-owned Hermes wrapper with provider `openai-codex`, model `gpt-5.6-sol`, and requested reasoning `high`. Authorized defect recovery uses a distinct fresh direct Codex session with the same model, `high` reasoning, and ordinary ceiling, followed by a separate fresh independent review. Independent review uses a distinct fresh direct Codex `gpt-5.6-sol` session with requested reasoning `xhigh`. The ordinary ceiling is exactly 60,000 tokens. An independent review is preclassified at 90,000 tokens; 120,000 is permitted only when the complex-review reason, fingerprint, and scope were recorded before invocation. Implementation cannot promote its ceiling. Unsupported invocation configuration stops unchanged and consumes no candidate attempt.

One automatic verification-only continuation may be consumed atomically for an exact actionable fingerprint only after implementation is recorded complete and the exclusive stop reason is a tool, session, or token ceiling. No check may have failed or remain known failing, no relevant worker may remain, and no product edit, policy question, scope change, secret, protected operation, or destructive action may be involved. The continuation is limited to verification, independent review, publication, or state finalization and cannot grant another continuation. A real failed check leaves this path and enters the ordinary bounded in-scope repair path.

Failures are classified before counters change. Pre-model infrastructure failures release reservations and consume no implementation, verification, review, or repair attempt. Gateway/network, unsupported configuration, invalid delivery, ceiling, repeated call, deterministic test, fixture, review, publication, remote CI, state reconciliation, overlap, Owner-policy, protected-operation, and repository-integrity failures remain distinct durable records. Ordinary authorized defects have at most two attempts per stage and exact fingerprint. Protected decisions never inherit that authority.

Repeated calls are keyed by normalized identity and arguments plus exact repository, compact-state, process-state, and prior-result category. An unchanged failed call is suppressed before a second non-progressing retry, while its safe underlying exit/category evidence and exact next eligible action remain visible. Completed, blocked, oversized, exhausted, continuation-used, and published markers are written atomically for the exact fingerprint; changed actionable fingerprints remain eligible.

The supervisor lock records PID plus verified process identity. A lock is stale only when that identity is absent or mismatched; age alone cannot recover it. Dispatch also refuses relevant Hermes, Codex worker, test, database-test, dispatcher, or supervisor overlap. No terminal status depending on a marker may be returned before that marker is durable.

Every model usage record contains returned model, returned reasoning when exposed, invocation route, session ID, input/cache-read/output/reasoning tokens, applicable ceiling, stage, result, repository fingerprint, and exact next action. A provider-omitted field is recorded exactly as `unavailable from provider`; it is never inferred. Gateway, fallback, implementation, later cycle, review, verification, ceiling, publication, and reconciliation events are never concatenated.

Publication requires foreground-observed deterministic gates, a fresh independent `passed: true` verdict, an exact reviewed path allowlist, clean scope/secret/canonical/diff checks, no overlapping process, a normal push, successful GitHub Actions, and local/upstream/remote equality. Compact state is then reconciled before model-free selection of the next exact durable-roadmap successor.

Health reporting distinguishes intentionally disabled, unhealthy, healthy idle, Owner-policy blocked, protected-operation blocked, implementation, verification, review, publication, reconciliation, recovered, completed, and repair-exhausted states. Notifications are deduplicated by notification type plus material state fingerprint and always state the affected subsystem, scheduler enabled state, project stage, cause, recovery state, exact next action, and whether Owner action is genuinely required.

Never broaden roadmap scope, invent canonical/product/security policy, handle secrets or production access, perform destructive operations, force-push, rewrite history, or publish with a failed or unobserved gate.
