answer each named business-state refusal with its own code (owner answer of 2026-10-05), and
`POST /refund-drafts` takes `"variant": "CREDIT_CUSTOMER"` for a Credit released to another
Customer (BR-CREDIT-014). No migration. Built on 2026-10-24 in the cloud session on the 11a and
11b work. Decisions on the findings below: decided by Claude under the owner's 2026-10-23 22:30
rule (no money, no who-may-do-what). The commit hash is in `git log` (this record is part of
that commit).

## Round 1 (read-only review agent, no files written)

No blocker. All 11 keys of the Refund table and the 11a table match a message the database
raises today, on the named paths.

- S1, fixed: "Refund Method is not active" is also raised for an id that never existed, so on
  `POST /refund-drafts` it now answers 422 `REFUND_METHOD_NOT_AVAILABLE` on `refund_method_id`;
  at confirm it stays 409 `REFUND_METHOD_OFF`.
- S2, fixed: on record, a recipient who is not a Signer is bad input: 422
  `REFUND_RECIPIENT_NOT_A_SIGNER` on `recipient_customer_id`; at confirm it stays 409.
- S3, fixed: the reversal of a return that was already reversed answers 409
  `REFUND_RETURN_ALREADY_REVERSED`; `REFUND_RETURN_REVERSAL_REFUSED` now says the money of the
  return is no longer available to reverse.
- S4, fixed: the shared confirm applies the Refund table to Refund drafts only, so a correction
  draft is never told to "use a post-settlement correction".
- S5, fixed: confirm maps "already decided" to `DRAFT_ALREADY_DECIDED`, a waiting Deposit receipt
  reversal draft to `REFUND_DEPOSIT_RECEIPT_REVERSAL_WAITING`, and an ordinary Credit draft for a
  released Credit to `REFUND_CREDIT_FOR_ANOTHER_CUSTOMER` (pointing to the `CREDIT_CUSTOMER`
  variant); the returns map a closed Final Settlement's Pet Deposit Refund to
  `REFUND_RETURN_THROUGH_CORRECTION` and return evidence that is not exact to 422
  `REFUND_RETURN_EVIDENCE_NOT_EXACT` (was 503). Kept: "Qualified Pet Refund source not found"
  stays a hidden 404, and "Refund source, amount, authorization or chronology is invalid" keeps
  its plain answer, because the same text also covers bad input (slice 12 list).
- S6, fixed: `test_financial_draft_api_migration.py::test_every_named_refusal_message_is_still_raised_at_head`
  checks every key of both tables and the Lease End Date message against the functions at head.
- Nits, fixed: the CREDIT_CUSTOMER answer must carry that variant (else 503); recipient fields
  with the variant answer 422; `REFUND_PAYER_HAS_UNPAID` cites BR-REFUND-003; the tables are
  read-only mappings; route tests per message and route, a Credit route mapping, a read never
  remapped, an out-of-date draft staying `DRAFT_OUT_OF_DATE`, and a named conflict answered
  without a second read. The draft id that includes the variant is documented in docs/005.
