# V1-056 slice 11c-3 review record: Deposit forfeiture, Deposit correction and returned-Payment draft routes

Built 2026-10-24 in the cloud session on branch `wip/slice-11` after 97fcc5d. No migration.

## What was built

- `backend/src/property_rental/draft_record_api.py` (new): four record routes over the existing
  services, each with `Idempotency-Key`, the browser mutation rules, a strict JSON body and a
  hidden 404 without the route's prepare capability:
  - `POST /properties/{p}/deposits/{deposit_id}/forfeiture-drafts` (`deposits.dispose`);
  - `POST /properties/{p}/deposit-dispositions/{disposition_id}/reversal-drafts` (`deposits.correct`);
  - `POST /properties/{p}/deposit-receipts/{receipt_id}/reversal-drafts` (`deposits.correct`);
  - `POST /properties/{p}/payments/{payment_id}/return-drafts` (`payments.reverse`).
- Named business-state refusals answer 409 with their own codes (`api_refusals.py`), at record and
  at the shared confirm (`financial_draft_api.CONFIRM_REFUSALS` for kinds `DEPOSIT_FORFEITURE`,
  Lease and receipt variants only, and `PAYMENT_RETURN`). An id the form chose that another record
  uses answers `DRAFT_RECORD_ID_IN_USE`; a reused key with other input `IDEMPOTENCY_KEY_REUSED`.
- The messages were read from the head catalog (temporary probe test, not committed) and the
  named-message guard (`test_financial_draft_api_migration.py`) now covers them.
- docs/005 paragraph "V1-056 slice 11c-3" after API-042.

## Review round 1 (one read-only agent)

No blocker.

- S1 (fixed): a stale Lease forfeiture, forfeiture reversal or receipt reversal draft answered
  422 at the shared confirm (the services raise their invalid error for 23514). The three stale
  messages now answer 409 `DRAFT_OUT_OF_DATE`; test added.
- N2 (fixed): the record answer check accepted a Deposit draft with no variant and did not compare
  the record the path names. It now needs the exact variant (none for a returned Payment) and the
  path's `deposit_id`, `disposition_id`, `receipt_id` or `payment_id`; test cases added.
- N3 (fixed): Reservation Deposit drafts share the kind `DEPOSIT_FORFEITURE`; they keep their
  plain confirm answers (`_confirm_table`); test added; docs say so.
- N4 (left as is): a service authorization error after the route's capability check answers 403
  here and 404 in `credit_refund_api`; it is reachable only for an inactive actor or an invalid
  actor id, and the shared draft routes also answer 403.
- N5 (fixed): tests for a used disposition id and a closed Final Settlement through the
  forfeiture service's own errors, and for an `X-Billing-Actor-ID` other than the signed-in person.
- N6 (fixed): docs give the 500-character reason limit of the forfeiture reversal too. The mapping
  of "The termination record is ambiguous" to `DEPOSIT_FORFEITURE_NO_GROUND` stays.
- The committed test `test_only_a_refund_draft_confirm_names_its_database_refusals` keeps its name
  (its traceability entry is append-only); its docstring now says that Deposit and returned-Payment
  drafts name theirs too since this slice.
