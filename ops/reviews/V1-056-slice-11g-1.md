# V1-056 slice 11g-1 review record: the automatic late-payment charge

Built 2026-10-25 in the cloud session on branch `wip/slice-11` after 27b887e. Migration
`20270210_198_automatic_late_payment_charge` (head). Decision log DL-085.

## What was built

- At 00:00 Property time on the first day after an Invoice's Due Date the billing worker's pass
  adds one late-payment charge of 10 percent of the amount unpaid at that moment, rounded half-up
  to the cent (DL-076 answers 1 to 3). No person decides; the Property's `billing.generate`
  service principal is recorded in the new columns `finalized_by_service` and
  `created_by_service`.
- Owner answer (card, 2026-10-25 01:43, "No charge"): an Invoice already overdue on the day the
  pass first runs gets no charge. The database itself refuses a charge for a day before
  `app.late_payment_first_charge_day`, both in `app.record_automatic_late_payment_charge`
  (`NOT_IN_WINDOW`) and in the decision check.
- `app.late_payment_charge_runs` (append-only, no grants) records each finished day; the next
  pass covers the days after the last one.
- `property_rental.late_payment_job`: one connection per pass, one READ COMMITTED transaction per
  Invoice, logs only counts and SQLSTATE codes. The worker runs it under its lock after the
  billing runs and reports a pass it could not run by code only.
- Also fixed: three `test_financial_action_context_migration.py` tests broken by slice 11c-1
  (migration 197 added `recovery` to each Refund read correction; the action context reads only
  value corrections, whose recovery is null). Test change only.

- Blocker (fixed): the first-day window was only in the candidate list, not in the record

- Fixed: a distinct message for a service principal's manual decision; no grants on the run

## Review round 2 (two read-only agents: database, error handling)

No blocker. Fixed:
- An outcome the code does not know counts as a failure (the day is not marked done past it).
- A refusal every later Invoice would get too (classes 08, 42, 53 and 22023) stops the pass at
  once; a lock wait, timeout or check on one Invoice stays with that Invoice.
- A window or outcome in an unexpected shape raises `LateChargePassError`, which the worker
  catches by name (no longer every `RuntimeError`).
- Tests: the lost-connection fake no longer marks timeouts as broken; the worker keeps its
  billing runs when the pass fails; the first-day test asserts the day is done; the catch-up
  test checks both sides of the window boundary; a trace note no longer claims paging.

Accepted and recorded (not fixed in 11g-1):
- One Invoice that fails on every pass keeps its day open, so each later pass re-reads the days
  since then. New days are still charged; the worker exits with failure and logs
  `late_charge_catch_up_days`. The failing Invoice is not named in the log (no Customer data);
  the operator finds it by query. Slice 12 list: record a failed Invoice so the day can close.
- A failure on the very first day moves the first day on (no charge for a day before a
  finished pass could see it).
- A first pass that runs past midnight may record its day with Invoices answered
  `NOT_IN_WINDOW` after midnight; an Invoice issued by hand with an issue time before 00:00 that
  commits after its page was read is missed. The worker issues its own Invoices before the pass.
- Counts cover the last attempt of a day only. A person may still record a WAIVE decision before
  the pass reaches an Invoice until slice 11g-3 removes the manual route.
- The first-day test needs the run outside the first 10 seconds of a Property day.
- The worker's outer idle transaction holds the lock while the pass runs on its own connection
  (before 11g-1 too); a lost worker connection ends the iteration with failure.
