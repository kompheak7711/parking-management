# V1-056 slice 11c-4 review record: walk-in Security Deposit and Deposit receipt routes

Built 2026-10-24 in the cloud session on branch `wip/slice-11` after 4a3f40b. No migration.

## What was built

- `backend/src/property_rental/deposit_api.py`: two routes over the existing Deposit service
  commands, each with `Idempotency-Key`, the browser mutation rules, a strict JSON body and a
  hidden 404 without the route's capability:
  - `POST /leases/{lease_id}/security-deposit` (`deposits.manage`; Q-2026-10-17-124 point 1):
    a walk-in Lease's Security Deposit; answers the Deposit resource and its `Location`;
  - `POST /deposits/{deposit_id}/receipts` (`payments.allocate`, no draft; Q-2026-10-12-92):
    a receipt from a received Payment into any existing Deposit; answers the receipt and the
    Deposit's money only, with no `Location`, because a holder of `payments.allocate` alone may
    not read Deposits (decided by Claude under the owner's 2026-10-23 22:30 rule; this person
    still sees the Deposit's required, held and outstanding money in the answer).
- Named business-state refusals by their database message (`SECURITY_DEPOSIT_REFUSALS`,
  `DEPOSIT_RECEIPT_REFUSALS`; codes in `api_refusals.py`), read from the head catalog; the
  named-message guard in `test_financial_draft_api_migration.py` covers them.
- Not built (decided by Claude under the owner's 2026-10-23 22:30 rule): the required-total
  adjustment route, because `app.adjust_deposit_required_amount` has no closed-Final-Settlement
  refusal (ops/V1_056_PLAN.md "11c-4 as built" gives the consequences and the next step).
- The Lease resource's `security_deposit_id` stays the one its draft named; changing it would
  also change the old move-in check (`lease_api.py`), so a walk-in Lease's Deposit is read from
  `GET /leases/{lease_id}/deposits`. The Deposit resource keeps
  `new_receipt_creation_deferred: true` for the current screens (its frontend type is the
  literal `true`; the screens are the rebuild thread's).
