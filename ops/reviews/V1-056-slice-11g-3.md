## Review round 2 (one read-only agent)

Round 1 fixes confirmed (each anchor occurs once; `eligible` is computed after the new blocker;
the preview raises `LATE_PAYMENT_DECISION_MISSING` only for an eligible review).

- Blocker (fixed, money): with the blocker gated on "the Property has any run", a Final
  Settlement could close between 00:00 on the charge day and the pass that writes the charge,
  and the pass then refuses the closed Settlement, so the charge would be lost. The blocker now
  needs a finished run on or after the Invoice's charge day (`business_date >= due_date + 1`).
  An Invoice overdue before the first pass still gets it, so that Settlement does not wait
  forever.
- Should-fix (fixed): tests for that window: the review has no new blocker while the last run is
  before the charge day; the preview still lists the Invoice with a run on the Due Date and lists
  nothing once a run covers the charge day.
- Nits taken: DL numbers in the migration (DL-087, DL-076 answers 1 and 4); DL-087 and the
  migration docstring say that after the first pass a malformed request to the old routes also
  answers 409; DL-087 says the new charge-read key appears in later audit states and replies, so
  its absence in an older record means nothing.
- Not changed: the old screen shows the raw blocker code, as it does for every other blocker;
  the V1-058 rebuild replaces that screen.

## Review round 3 (one read-only agent)

No blocker. The gate `business_date >= due_date + 1` is exactly "a finished pass has covered
this Invoice's charge day": a run row is written only after every candidate of the day was
looked at with no failure, and a run covers the charge days since the last run.

Should-fix, recorded (text only, run rule: no round 4):
- An Invoice paid in full after 00:00 on its charge day but before that day's pass is PAID, so
  the preview no longer reads it and a Final Settlement can close first; the pass then finds the
  Settlement closed and writes no charge. This dates from slice 11g-1, not this slice. Recorded
  in DL-087 and the migration docstring; slice 12 list: the preview also waits for a PAID Invoice
  whose charge day no run covers yet and that had a balance at its charge moment.
- A pass that stops after its first run leaves later charge days uncovered, so a Final Settlement
  with such an Invoice waits and no manual decision can clear it. Fails safe; recorded in DL-087
  and on the slice 12 list.

Nits taken: DL-087 says the decision form still shows (and answers 409) between the first pass
and the run that covers an Invoice's charge day; the test also pins `eligible is True` before
that run.
